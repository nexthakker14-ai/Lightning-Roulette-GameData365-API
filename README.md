# Lightning Roulette Rules Bot — GameData365

Бот отримує результати Evolution Lightning Roulette через GameData365 API, перевіряє чотири правила та надсилає повідомлення лише тоді, коли правило спрацювало.

## Правила
1. 6 однакових кольорів поспіль → сигнал на протилежний колір.
2. 6 однакових парностей поспіль → сигнал на протилежну парність.
3. 6 чисел поспіль у діапазоні 1–18 або 19–36 → сигнал на протилежний діапазон.
4. 4 числа поспіль в одній дюжині:
   - 1–12 → сигнал на 13–24 та 25–36;
   - 13–24 → сигнал на 1–12 та 25–36;
   - 25–36 → сигнал на 1–12 та 13–24.

**Нуль:** перериває всі серії; не є парним/непарним, червоним/чорним або частиною дюжин/половин.

## Railway Variables
- `GAMEDATA365_API_KEY` — новий API-ключ (не вставляйте ключ у код).
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_CHAT_ID` — ID групи; кілька ID можна вказати через кому.
- `TABLE_ID=lightning_roulette`
- `PROVIDER=evolution`
- `POLL_SECONDS=10` — мінімум у цьому проєкті 5 секунд; врахуйте ліміт API.
- `GAMEDATA365_API_URL=https://api.gamedata365.com/v1/live`

## Deploy
Завантажте в GitHub і під'єднайте репозиторій до Railway як Worker. Додайте Variables. Railway запускає `python main.py`.

## Важливі примітки
- Під час першого запуску бот починає формувати серії з результатів, які API повертає як поточні (`backfilled=false`). Він не створює сигнали з історичних/backfilled результатів.
- Для уникнення повторів використовується ID раунду, якщо API його надає.
- Парсер підтримує типові назви JSON-полів. Реальний JSON акаунта ще потрібно звірити; якщо назви полів відрізняються, адаптуйте `parse_record()` у `main.py`.
- Це інформаційні сигнали, бот не робить автоматичних ставок.
