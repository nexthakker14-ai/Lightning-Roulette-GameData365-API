# Lightning Roulette Rules Bot — GameData365

Бот отримує нові результати Evolution Lightning Roulette через GameData365 API та надсилає окреме повідомлення для кожного правила, яке завершило серію.

## Правила сигналів

1. **Колір:** 6 червоних поспіль → ставка на чорне; 6 чорних поспіль → ставка на червоне.
2. **Парність:** 6 парних поспіль → ставка на непарні; 6 непарних поспіль → ставка на парні.
3. **Діапазон:** 6 чисел 1–18 → ставка на 19–36; 6 чисел 19–36 → ставка на 1–18.
4. **Дюжини:** 4 числа з першої дюжини (1–12) → друга та третя; 4 з другої (13–24) → перша та третя; 4 з третьої (25–36) → перша та друга.

## Перевірка сигналу

- Сигнал надсилається тільки після повного формування серії: на 6-му або 4-му результаті відповідно.
- Нуль перериває всі серії. Для вже активного сигналу нуль рахується як одна з наступних 10 спроб, але не може бути WIN.
- Одночасні сигнали за різними правилами надсилаються окремими повідомленнями.
- Після сигналу перевіряються наступні 10 чисел, не включаючи число, на якому сформувався сигнал.
- WIN фіксується при першому випаданні будь-якої цільової категорії; повідомлення містить номер спроби.
- Якщо за 10 чисел ціль не випала — LOSS.
- Повторний сигнал не створюється на 7-му, 8-му тощо числі тієї самої безперервної серії. Потрібна нова серія після переривання.
- PRE-ALERT та попередження відсутні.

## Railway Variables

- `GAMEDATA365_API_KEY` — API-ключ (не вставляйте ключ у код).
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_CHAT_ID` — ID групи; кілька ID можна вказати через кому.
- `TABLE_ID=lightning_roulette`
- `PROVIDER=evolution`
- `POLL_SECONDS=10` — мінімум 5 секунд; врахуйте ліміти API.
- `GAMEDATA365_API_URL=https://api.gamedata365.com/v1/live`

## Deploy

Завантажте файли в GitHub та під'єднайте репозиторій до Railway як Worker. Додайте Variables. Railway запускає `python main.py`.

## Примітки

- Бот обробляє тільки результати, які API позначає як нові (`backfilled=false`).
- Для уникнення повторної обробки використовується ID раунду, якщо API його надає.
- Парсер підтримує типові назви JSON-полів; фактичну структуру відповіді API потрібно звірити за потреби.
- Стан серій та активних сигналів зберігається у `state.json`.
- Це інформаційні сигнали; бот не виконує автоматичних ставок.
